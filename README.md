# Клинический компас

Инструмент поддержки принятия клинических решений при ведении взрослых (18+) с тревожными и депрессивными симптомами.
Система **предлагает**, врач **решает**: назначение, направление к психиатру и смена статуса динамики создаются только после подтверждения врачом.
Диагноз устанавливает врач. Система скорую помощь не вызывает: пациенту показываются инструкции и номера 112 / 103.

## Быстрый старт (Mac / Linux)

```bash
./run.sh
```

Откройте <http://127.0.0.1:8000/> — веб-приложение (кабинеты врача, дежурного, психиатра, администратора и мобильное приложение пациента). Документация API: <http://127.0.0.1:8000/docs>. Демо-пользователи, пароль у всех `demo12345`:

| логин | роль |
|---|---|
| `doctor1` | лечащий врач (5 синтетических пациентов S1–S5) |
| `doctor2` | другой врач (чужих пациентов не видит) |
| `duty`, `clinic_admin`, `staff` | дежурный врач, администратор смены, ответственный сотрудник |
| `psychiatrist` | психиатр (входящие направления, PDF, экспорт) |
| `admin` | администратор (конфигурация, очередь, журнал; клинических данных не видит) |
| `patient_s1` … `patient_s5` | пациенты (мобильное приложение — API `/api/patient/*`) |

Тесты: `./run_tests.sh` (95+ проверок). Замеры: `python backend/scripts/benchmark.py`. Оценка импорта: `python backend/scripts/eval_import.py`.

## Что уже работает

* Все 8 задач инструмента на уровне API: анкета и шкалы, карточка врача, правила алертов и маршрутизации, проверка препарата (5 состояний, «неизвестно» никогда не становится «противопоказаний нет»), мониторинг и коммуникации, импорт, реестр источников, слой интеграции.
* Алерт-пайплайн: красный — сразу и круглосуточно лечащему врачу и ответственному, через 5 минут дежурному, через 10 — администратору смены; оранжевый вне рабочего времени ставится на начало следующего рабочего дня; «не удалось связаться» красный алерт не закрывает; закрытие требует обязательных полей.
* Очередь доставки: идемпотентность, повторы с нарастающей паузой, запасной канал, эскалация при сбое. Каналы push/SMS — адаптеры-заглушки.
* Вся клиника — в `config/*.json`; новые шкалы, правила и тексты добавляются без изменения кода (`PUT /api/admin/config/files/{name}` с полной проверкой).
* Безопасность: пароли PBKDF2, токены хранятся хешем, персональные поля шифруются (Fernet), журнал аудита, проверка роли на каждом запросе, согласие обязательно до ввода данных.

## Чего ещё нет

* Офлайн-режима и иконок PWA (манифест есть, service worker нет).
* Реальные SMS / push-провайдеры и реальная МИС (интерфейс адаптеров готов).
* Всё, что помечено «ЖДЁМ» в конфигурации (см. `docs/OPEN_ITEMS.md`).

Документация: `docs/ARCHITECTURE.md`, `docs/OPEN_ITEMS.md`, `docs/benchmarks.md`.

## Фронтенд

`frontend/` — React + Vite. Готовая сборка в `frontend/dist` раздаётся бэкендом. Пересборка: `cd frontend && npm install && npm run build`. Разработка: `npm run dev` (прокси на бэкенд :8000).
Пациент открывает ссылку-приглашение `/#/join/КОД` (QR показывает врач при создании карточки).
