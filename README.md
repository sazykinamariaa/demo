# Клинический компас

Инструмент поддержки принятия клинических решений при ведении взрослых (18+) с тревожными и депрессивными симптомами.

**Система предлагает, врач решает.** Назначение, направление к психиатру и смена статуса динамики создаются только после подтверждения врачом. Диагноз устанавливает врач. Система не вызывает скорую помощь: пациенту показываются инструкции и номера 112 / 103.

## Что внутри

Четыре рабочих кабинета и приложение пациента в одном веб-приложении:

- **Врач** — список и карточки пациентов, анкеты и шкалы, динамика, проверка препарата, предложения системы (назначение, направление, смена статуса) с подтверждением врачом, сообщения пациенту, создание нового пациента и приглашение по QR.
- **Дежурный врач / администратор смены** — оповещения с эскалацией и обязательным закрытием.
- **Психиатр** — входящие направления, карточка пациента, динамика, рекомендации с обязательным комментарием к решению, план, сообщения.
- **Администратор** — конфигурация, очередь доставки, журнал аудита (клинических данных не видит).
- **Пациент** — мобильный интерфейс: согласие, анкета и шкалы, ежедневные отметки, сообщения. На экранах пациента нет красного цвета.

## Быстрый старт (Mac / Linux)

```bash
./run.sh
```

Откройте <http://127.0.0.1:8000/>. Документация API: <http://127.0.0.1:8000/docs>.
Первый запуск сам создаёт окружение и ставит зависимости (нужен Python 3.10+; если его нет, скрипт ставит `uv`). На Mac можно запускать двойным щелчком по `Запустить.command` (если файл есть в поставке).

Параметры запуска (переменные окружения):

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `KK_SEED` | `1` — создать стартовых пользователей и пациентов S1–S8 (повторный запуск ничего не дублирует), `0` — чистая база | `1` |
| `KK_INIT_PASSWORD` | начальный пароль всех стартовых логинов | `Kompas2026x` |
| `KK_HOST` | адрес прослушивания; `0.0.0.0` — доступ из локальной сети | `127.0.0.1` |
| `KK_DATA_DIR` | папка базы данных и ключа шифрования | `./data` |
| `KK_SECRET_KEY` | ключ шифрования вместо файла `data/secret.key` | создаётся файл |
| `KK_DATABASE_URL` | PostgreSQL вместо SQLite | SQLite |

## Стартовые логины

Пароль у всех — `Kompas2026x` (или значение `KK_INIT_PASSWORD`). Смените его перед использованием вне демонстрации.

| Логин | Роль |
|---|---|
| `doctor1` | лечащий врач (пациенты S1–S5) |
| `doctor2` | другой врач (пациенты S6–S8, подтверждённые психиатром; чужих пациентов не видит) |
| `duty`, `clinic_admin`, `staff` | дежурный врач, администратор смены, ответственный сотрудник |
| `psychiatrist` | психиатр |
| `admin` | администратор системы |
| `patient_s1` … `patient_s8` | пациенты (синтетические) |

Все пациенты в стартовых данных вымышленные. Пациент может также зарегистрироваться по ссылке-приглашению `/#/join/КОД`, которую врач выдаёт (QR) при создании карточки.

## Как это устроено

- **Бэкенд:** FastAPI, SQLAlchemy 2.0, SQLite (по умолчанию) или PostgreSQL. 35 таблиц, схема описана в `docs/СХЕМА_БД.md`.
- **Фронтенд:** React 18 + Vite. Готовая сборка лежит в `frontend/dist` и раздаётся бэкендом. Пересборка: `cd frontend && npm install && npm run build`; разработка: `npm run dev`.
- **Вся клиника в `config/*.json`:** шкалы, правила оповещений и маршрутизации, тексты. Новые шкалы и правила добавляются без изменения кода (`PUT /api/admin/config/files/{name}` с проверкой).
- **Единственное место, где создаются назначение, направление и смена статуса, — `proposals.py`**: только после подтверждения врачом.
- **Оповещения:** красный — сразу лечащему врачу и ответственному, через 5 минут дежурному, через 10 — администратору смены; оранжевый вне рабочего времени переносится на начало рабочего дня; «не удалось связаться» красное оповещение не закрывает; закрытие требует обязательных полей.
- **Очередь доставки:** идемпотентность, повторы с нарастающей паузой, запасной канал, эскалация при сбое. Каналы push/SMS — адаптеры-заглушки.
- **Проверка препарата:** 5 состояний; «неизвестно» никогда не превращается в «противопоказаний нет».

## Безопасность

Пароли — PBKDF2; токены хранятся хешем; персональные поля шифруются (Fernet); журнал аудита; проверка роли на каждом запросе; согласие обязательно до ввода данных. Файлы `data/` (база и `secret.key`) никогда не публикуются.

## Чего ещё нет

Офлайн-режима и иконок PWA (манифест есть, service worker нет); реальных SMS/push-провайдеров и МИС (интерфейс адаптеров готов); всего, что помечено «ЖДЁМ» в конфигурации (см. `docs/OPEN_ITEMS.md`). Часть клинических порогов намеренно не задана и требует решения врачей.
